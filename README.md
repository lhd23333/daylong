# 朝夕 · 陪你过完这一天

一个跑在本机的陪伴型应用。把一天的日程放进去，它会替你算出**该在什么时候休息**、
写一句话**问候你今天的状态**，并在休息的那一刻**当场生成一段适合你的音乐**。

面向的场景很具体：高中生的一天被课表和自习切得很碎，真正能走开的空档不多，
而人一旦坐下来就很难自己想起来要起身。所以这个项目做的不是"再推荐一首歌"，
而是**把休息本身安排出来，并且让那段休息真的待得住**。

服务端只用 Python 标准库，浏览器端依赖固定版本的 Tone.js 并随包提供，**全程离线可用**。

## 它长什么样

四个页面（打开应用停在「对话」页）：

- **对话** —— 说一句今天怎么过（几点上课、想不想跑步、今天累不累），它把话排成日程与
  音乐。排出来的东西摊在同一页：时间轴、配上的音乐、记住的喜好；下面给两个去处——
  「写进今天」（写日程 + 写状态 + 跳到「今天」页）与「听这段」（跳到「休息」页并开始
  播放）。对话存在浏览器本地（`localStorage`），刷新不丢，「重新说」清空。
- **今天** —— 顶部是一张关怀卡（问候 / 依据 / 建议），下面是一张「今天的声音路线」卡
  （把当天的曲子与休息音景串成一条能连播的节目单），再往下是整天的时间轴。日程和
  休息点串在同一条线上，中间插一根「现在」标尺。还没到的休息点是一张立起来的小卡片，
  过去的休息点收起卡片形态、退回成普通条目——卡片意味着"还用得上"。
- **了解你** —— 状态三个滑杆（精力 / 压力 / 专注）+ 睡眠与久坐时长、作息时间、
  今天的日程（手动添加或导入 `.ics`）、以及喜欢的音景。
- **休息** —— 选一个音景开始播放。中间是一张**在转的光碟**，转速跟着 BPM 走；
  频谱绕成碟外的一圈（96 根径向柱子），周围是跟着音乐动的粒子。下面有节拍 /
  节奏量 / 音乐 / 鼓点四个滑杆、「换一段」与「收藏」两个按钮，以及一个默认展开的
  「自己调这一段」面板（调性 / 和声进行 / 鼓点 / 粒子驱动规则）；再往下是「我的收藏」
  列表。还没开始放的时候，光碟整体压暗、节拍 / 节奏量两个滑杆是灰的——一张空转
  的碟看着像坏了，也不该让人对着一组还不存在的参数拖。另有可选的一条"让 AI 直接
  生成一段音频"通道。

## 一天是怎么被排出来的

1. 前端把当前时间、当天的起止窗口、状态和作息发到 `POST /api/day`。
   不传 `events` 时后端用它自己保存的日程，避免两份数据打架。
2. `music_companion/day_plan.py` 把一天的窗口切成若干段：不可打断的日程是
   `protected`，其余是 `free_windows`。
3. 在两类位置安排休息点：
   - **可打断的长块内部**：一段超过 90 分钟的学习/工作，在第 90 分钟安排一次
     「出去走一圈」；
   - **空闲窗口**：按"已经连续学了多久"和"这个空档装得下什么"从
     walk / stretch / breathe / eyes / water 五类里挑。
4. 挑选时**优先选当天还没出现过的那一类**，而不是顺着固定的级联一路 `elif` 到底。
   这一条是为了避免一天下来四个休息点全写着「出去走一圈」——那读起来像机器排的。
5. `music_companion/soundscape.py` 按 **时段 +3 / 心情 +2 / 场景 +2 / 精力 +1**
   的打分制挑音景，同分时按 id 字典序取第一个，所以**同样的输入在任何机器上都得到
   同一个结果**。
6. `music_companion/companion.py` 把日程与状态整理成一组"事实"（睡了多久、距下一件
   还有几分钟、最长空档多长……），再从中选一条模板生成关怀语。模板里引用了空事实的
   措辞会被 `_usable()` 过滤掉，不会渲染出「还有  分钟」这种病句。
7. 返回一份 `timeline`：日程和休息点混排，每个休息点带 `soundscape` / `bpm` /
   `intensity` / `reason`。

## 音乐为什么不是循环播放

这是项目里唯一"重"的部分，也是最花心思的地方。

**没有音频文件。** 休息点的音乐是浏览器用 Web Audio 现场合成的，曲谱由算法即时决定：

- `static/js/theory.js` —— 音乐理论的翻译层。和声进行写成 `["2min9", "5dom9",
  "1maj9", "6min9"]` 这样的**级数记号**，好处是同一套进行可以搬到任意调上。
- `static/js/soundscapes.js` —— **程序库**。18 个音景，覆盖 lo-fi、city pop、轻音乐、
  古典、摇滚、重金属、电子、8-bit、爵士摇摆等风格，每个定义了性格、适用时段、
  心情、场景、5～7 条级数进行、每小节几拍换和弦、4 个声部（键盘 / 铺底 /
  铃音 / 贝斯）各自的音色、八度、增益和演奏方式，外加一条 **bpm 推荐区间**、
  一条 **density（节奏量）推荐区间**和一个 **鼓点推荐档位**（`groove.drumLevel`）。
  失真吉他类音色在引擎里额外接一道 `Tone.Distortion` 削波（音量给在失真之后，
  否则大小声会被削平成一样响）。
- `static/js/engine.js` —— 引擎。用 Tone.js 搭一条
  `bus → 滤波 → 合唱 → 混响 → 限幅 → 主输出 → 电平表/频谱 → 扬声器` 的链，
  外加一条 `滤波 → 反馈延时 → 混响` 的并行送出。鼓组不走这条链：它自己一条总线，
  绕开低通 / 合唱 / 延时 / 混响直接进主输出——拍子要干、要紧。每小节现算要弹哪些音，
  用固定种子的伪随机数决定琶音与留白，所以**同一段音乐可以复现，但不会原地循环**。

每个休息点用自己的 id 当随机种子，所以**同一个音景在不同休息点会落到不同的调性上**，
不会一整天听着同一段。

传输层是自己写的小节调度器，不是 `Tone.Loop`，锚点也**不用秒而用 tick**（音乐时间）。
原因有两层，都记在 `engine.js` 的注释里：`Tone.Loop` 按"回调收到的音频时间 + 构造时
算出的固定秒数"自我重排，两个时间基准会漂移；改用绝对秒数之后，`schedule()` 会按
**当时的 BPM** 把秒数一次性折算成 tick，而每次写入 BPM（换音景、拖速度）都会让 tick
计数器重算原点——两个刻度从第一次换音景起固定错开，事件落到错误的 tick 上，听感就是
演奏中随机静默 1~5 秒（实测并修复于 2026-10-05）。现在一小节恒为 4×PPQ = 768 tick、
与 BPM 无关，回调里先摘掉自己的事件再排下一节，每次起链显式把计数器归零、由引擎
自己定义网格原点。摇摆（swing）也走同一套：Tone 的 `Transport.swing` 只摆动传给回调
的时间、够不到小节内部用绝对偏移排的音符，所以按同一公式在偏移上自己加（正拍恒零、
八分反拍最大，爵士音景 swing 0.5 即标准三连音摇摆）。

## 四条轴是分开的，推荐不是手铐

**音景 / 节拍 / 节奏量 / 鼓点**是四条独立的轴。早先每个音景把速度写死成一个硬边界，
用户只能在 8 个预设里挑；现在音景上写的那段区间**降级成推荐值**：

- 真正的硬边界上移到全局：**bpm 40–200、density 0–1**。滑杆只能拖到这个范围内，
  但在范围内拖到哪都合法。
- 滑杆轨道上用暖色画出当前音景的推荐区间。拖出区间**照样能放**，界面只在下面用
  一行字说明「这一段原本不是为这个速度写的」——不阻止、不弹窗。推荐是方向，
  不是手铐；完全不给方向又会让人面对一堆滑杆不知道该往哪拖。
- **鼓点**是离散的四档：无 / 轻 / 标准 / 强。每个音景有自己的推荐档位，界面按当前
  音景把它标出来；换音景推荐会跟着变，选别的档也照样能放。音乐与鼓点各有一条音量
  滑杆（默认 62 / 85）——拍子不用等人来改混音，自己就能拧上来。
- 另外两个自由维度：**调性**（12 个调 + 「自动」）与**和声进行**（当前音景的几条
  + 「自动」）。选「自动」＝ 按种子在音景的推荐表里挑；手动选了就钉住，之后点
  「换一段」不会动它。
- 组合数按**全局**节拍档位（40–200 逐档）算，而不是按各音景自己的那一小段——
  解耦之后速度本来就能拖出去，按推荐区间计数等于在计数上偷偷把解耦收回来。
  页面上「音景」标题右侧会实时报出音景数、进行总数、调性数与总组合数。
- 当前这一版的数是 **18 个音景 × 各自的调性 × 各自的和声进行 × 161 个节拍档位
  × 4 个鼓点档位 = 305900 种组合**（各音景展开后相加：19320 / 22540 / 19320 /
  12880 / 19320 / 12880 / 19320 / 12880 / 12880 / 12880 / 19320 / 19320 / 16100 /
  19320 / 16100 / 16100 / 19320 / 16100）。节奏量是连续量，
  没有"档位"可言，所以不参与计数——界面上单独说明。

## 收藏存的是配方，不是音频

整条合成链路是确定性的（种子驱动的 mulberry32 伪随机数），所以**同一组字段永远得到
同一段音乐**。一份配方就是八个字段：`{styleId, bpm, density, key, progressionIndex,
drums, seed, name}`。于是"收藏一首好听的曲子"不需要保存任何音频文件——不占空间，
也不怕文件丢。

- 条目 id 是**配方的 uuid5 纯函数**（固定命名空间，不含时间也不含计数器），跨进程、
  跨机器稳定，所以"这段音乐是不是已经收藏过"有确定答案。
- 越界输入**一律报错而不夹紧**（bpm 40–200、density 0–1、seed 为 uint32）：夹紧会让
  存下来的配方与用户当时听到的不是同一段音乐，而"下次还能听到同一段"正是收藏的
  全部意义。
- 单文件上限 500 条（约 100 KB）。到顶**报错而不是淘汰旧条目**——收藏是用户资产，
  不能因为收藏了新歌就悄悄丢掉旧歌。
- 落盘 `data/playlist.json`（已在 `.gitignore` 里），写盘走"临时文件 + `os.replace`"。
  整份 JSON 损坏时改名备份后重建；单条坏数据只丢那一条。

## 日程会变成旋律，还会提前叫你

`static/js/daymusic.js` 是一条纯逻辑链（不碰 DOM，可以单独理解和测试）：把日程标题
关键词、类别、开始时间所处时段、任务时长和当天的精力 / 压力快照推成一段旋律。
三条设计原则：

1. **确定性**。整条推导链上没有 `Math.random()`，随机部分走 FNV-1a 哈希 + 种子。
   同一个标题 + 同一天永远推出同一首——明天再看这条日程，听到的还是昨天那段。
   随机配乐让人觉得是机器在放背景音；稳定的对应关系才会产生"这是我这门课的曲子"
   的归属感。
2. **可说理**。每条推导附一句 `why`，界面上直接显示。用户看到的不是"AI 配了一首歌"，
   而是"因为你 21:00 要睡觉，所以给你一首 62 BPM、音符很少的夜灯"。
3. **不越权**。推出来的 bpm / density **夹回该音景的推荐区间**，而不是全局硬边界——
   音景的辨识度来自它自己那一段，为了"贴合日程"把它推到区间外，推出来的就不再是
   那个音景了。

「今天」的时间轴上，每条日程下面会显示配到的音景与 BPM（如「♪ 书桌前 · 69 BPM」），
右侧有「放这首」按钮。

**提醒**：日程开始前 **5 分钟**在右下角弹一张卡，显示"还有 N 分钟"、日程标题和那句
`why`，并提供「先听一段」（休息点用各自更紧的提醒值，1–3 分钟）。**边界：只在页面
开着时有效**——浏览器关掉没有后台能力，这一点不假装。页面在窗口期内才被打开也会补
触发：13:58 才打开页面，13:57 该响的那条不会被吞掉。

## 一整天可以连成一条声音路线

日程有自己的旋律、休息点有自己的音景、换段之间是无缝 crossfade——单独看是三件事，
串起来才是"陪你过完这一天"。`static/js/dayqueue.js`（同样是纯逻辑，不碰 DOM）把当天
时间轴翻成一条**节目单**：每件事一段曲、每个休息点一段音景，按时间排好，在「休息」页
一段接一段自动续上。入口是「今天」页的路线卡，按一次「开始收听」，剩下的路由它走。

- **段长克制在分钟级**（日程段 2 分钟、休息段 1 分半）：一天十几条全放完要好几个小时，
  没人这样听；一两分钟够听出"这是那件事的曲子"，整条路线大约十几分钟走得完。
- **和时间轴共用同一份配方**：路线里"语文课"那一段，和点时间轴「放这首」听到的逐字
  一致——两边都走 `daymusic.js` 的同一条推导，不存在"路线版"和"手动版"两套音乐。
- **计时跟着音频的小节回调走**，不自己开秒表：切去别的标签页也顶多晚半个小节换段，
  不会因为浏览器节流定时器而乱套。
- **方向盘始终在用户手里**：路线在走时手动点任何音景、任何「放这首」，自动退出连播；
  暂停再继续不算换台，回来接着听这一段；「了解你」里改了日程，重排后节目单跟着变。

## 频谱为什么绕成一圈

播放器中间是一张在转的光碟，每小节转八分之一圈——慢到几乎察觉不到在动，但盯着看
确实在转，于是"快"是看得出来的；碟心是 BPM 与调性读数。频谱没有拉成一条横条，而是
**绕成碟外的一圈 96 根径向柱子**：低频在正上方、顺时针铺开、频率越来越高。这样它
既是"那个在转的东西"，也仍然是真的频谱——读的是同一个 `engine.getSpectrum()`。

粒子（`static/js/particles.js`）是同一套分析的另一个消费者：`static/js/features.js`
把 256 点 FFT 归纳成 bass / mid / treble / rms / 谱心 / 拍点这些标量，粒子只读这些
标量、完全不碰原始 FFT。分层的好处是换视觉不用改分析——粒子有四种驱动规则
（重力场 / 径向爆发 / 湍流 / 星轨），在「自己调这一段」面板里切换。

## 启动

不需要 Flask、Node 包或任何第三方 Python 库，只要有 Python 3.10+。

Windows 可以直接双击项目提交目录里的 `一键启动朝夕.bat`，脚本会自动定位项目、
检查 Python、启动服务并打开浏览器。

```bash
cd 项目源代码
python server.py
```

然后打开 <http://127.0.0.1:8000>。停止按 `Ctrl+C`，换端口用 `--port 8080`。

运行测试（228 个用例，约 24 秒跑完）：

```bash
python -m unittest discover -s tests
```

> `tests/` 目录没有 `__init__.py`，所以**不要**加 `-t .`，否则会报
> `Start directory is not importable`。

## 连接 AI（可选）

不配任何密钥也能完整演示：关怀语走本地模板，音乐走浏览器实时生成。配上之后是几个
互不相干的增强通道——**文本通道改措辞，远端音频通道换声音**，各配各的，坏一个不影响
另一个。

密钥有两种填法，效果完全一样：

1. **页面上填（推荐）**：「了解你」页最下面展开「连接 AI（可选）」，填入对话和/或
   音乐的密钥，点「保存，立即生效」——不用重启。想改就再填一次，想收回就点「清除」。
2. 写 `.env` 文件（见下面的示例），适合部署或想把配置统一放在环境变量里的场合。

页面上填的值存在本机 `data/ai_settings.json`，与 `.env` 的关系是**设置优先、`.env`
兜底**：同一字段两边都有时用页面上的；页面上清除后就回到 `.env`。读接口只回显密钥的
**尾 4 位**做提示，完整 Key 不会再回到页面。两个文件都不进版本控制、不随作品提交
（打包脚本显式排除整个 `data/` 与 `.env`）。

「对话」页的理解同样有两条通道：**配了密钥时走模型，没配时走本地规则，两条通道同一个
输出结构**。模型通道只被要求输出 `HH:MM` 这种时刻，时区与 ISO8601 由 Python 拼；返回后
逐字段校验，不合法的字段单独退回本地值。模型没配、超时、报错或返回不合规，一律退回
本地结果，并在 `fallback_reason` 里留下原因——**不配 `.env` 也能完整演示**。

先说清远端音频通道的定位：网页上的音乐**默认全部由本地程序化合成器现场生成**——确定、
免费、离线可用。远端通路是**可选的加成**，不配也能完整演示；本地合成器是主线，不是
fallback。远端通路还分两家，由 `MUSIC_PROVIDER` 选择，两个客户端共用同一个
`build_music_prompt()`、对上层暴露同一个 `generate()`：

- `elevenlabs`（默认）—— 一次 POST 同步返回 mp3，需要能访问海外网络。
- `tempolor`（天谱乐）—— **中国大陆可直连**，异步任务，链路是"提交 → 轮询 → 下载"。
  它的 `callback_url` 是必填项，但本应用跑在 `127.0.0.1` 上收不到回调，所以改用官方
  的任务状态查询接口轮询取结果；该字段仍须填一个占位地址，**缺配置时明确报错而不替
  用户瞎编 URL**。

远端通路不可用时**不再拦住服务启动**：本地合成器才是主线。

关怀语的 AI 通道走 `AIRecommender.care()`：`POST /api/day` 会先把本地关怀卡算好
（它永远是完整的），再把它连同今天的客观事实交给模型重写三句话。模型返回的内容要过
`_care_from_ai` 的检查——空字段、超长、出现「加油」「你可以的」这类空话，一律丢弃，
仍然显示本地版本。所以**打开这个通道最坏的结果是措辞没变，不会是没有关怀语**。

```bash
cp .env.example .env
```

## 主要接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/soundscapes` | 音景目录（返回的是**裸数组**，不是包了一层的对象） |
| GET | `/api/calendar/events` | 日程列表，支持 `?date=YYYY-MM-DD` |
| GET | `/api/state/latest` | 最近一次状态快照 |
| GET | `/api/health` | 模式与能力探测，含远端音乐通路的配置状态 `remote_music` |
| GET | `/api/ai-settings` | 「连接 AI」设置现状：生效值与密钥**尾 4 位**提示（完整 Key 不出服务端） |
| POST | `/api/ai-settings` | 保存页面填的密钥并**立即生效**（热重建客户端，不重启）；字段缺席=保持、空串=清除 |
| DELETE | `/api/ai-settings` | 清除页面填的设置，回到 `.env` 的行为 |
| POST | `/api/agent` | 对话入口：把一段话读成日程与音乐。**接口本身只读**，不写入任何状态；退回本地规则时在 `fallback_reason` 里说明 |
| POST | `/api/day` | **主接口**：编排一整天，返回 timeline / stats / care |
| POST | `/api/day/break-status` | 标记某个休息点为 started / done / planned |
| POST | `/api/calendar/events` | 新增日程 |
| POST | `/api/calendar/import-ics` | 导入 `.ics` |
| DELETE | `/api/calendar/events/<id>` | 删除日程 |
| POST | `/api/state/manual` | 保存状态快照 |
| GET | `/api/playlist` | 收藏的配方列表（存的是八字段配方，不是音频） |
| POST | `/api/playlist` | 收藏一段；重复收藏同一段回 **200 + `duplicate: true`** 而不是 201 |
| DELETE | `/api/playlist/<id>` | 删除一条收藏 |
| POST | `/api/generate-ai-audio` | 调音乐模型生成音频，失败自动回落本地 WAV |
| POST | `/api/recommend` | 第一版的 BPM / 步频推荐（界面已不使用） |

日期时间字段一律要求**带时区**的 ISO8601（`2026-10-05T09:40:00+08:00` 或结尾 `Z`）。
不带时区会返回 400——这是刻意的，避免跨时区把休息点排错。

## 为什么这样设计

- **服务端只用标准库**。课堂电脑装依赖经常失败，而 `http.server` 零安装即可启动。
  需要"库"的地方（实时音乐）放在浏览器端，用固定版本随包提供，不依赖 CDN。
- **本地规则不是装饰，是基准**。关怀语、选曲和「对话」页的日程理解在没有网络时
  都是完整的，AI 只是把措辞和音频做得更好；任何一路失败都不影响主流程。
- **确定性优先**。选音景同分按 id 字典序、休息点 id 用 uuid5、音乐用固定种子——
  同样的输入在任何进程、任何机器上都得到同样的结果，便于复现和讲解。
- **能测的逻辑不放在前端**。编排、选曲、关怀语全在 Python 里，可以单独跑测试；
  前端只负责呈现和调度。
- **不假装**。AI 音频失败时响应头会写明 `X-Music-Source`，界面照实说"改用本地循环"，
  不把回退包装成成功。

## 已知限制

- 本地关怀语是模板 + 事实填充，不是真正理解长文本；AI 通道才会读用户写的备注。
- 「对话」页记住的喜好只用于当前这轮对话的上下文，不做跨对话的学习或长期画像。
- 休息点是按日程形状和状态推出来的，不理解"这节课特别重要不能打断"这类语义，
  需要用户把日程标成不可打断。
- **提前提醒只在页面开着时有效**。浏览器关掉就没有后台能力，可靠的后台提醒需要
  PWA / Service Worker 或手机端——这里不假装自己是常驻 App。
- 声音路线是当场生成的连播节目单，不是离线音频：关掉页面它也随之停下（同上的形态
  边界）；每段播一两分钟是刻意截取，不是"把这件事的曲子完整放完"。
- 频谱可视化只画到约 1 kHz 以上的一段（实测再往上已经低于噪声底），是呈现上的
  取舍，不是完整频谱。
- 服务器仅供本地开发与演示，没有鉴权、限流和 TLS。
- AI 音乐的时长、旋律与 BPM 与提示词存在偏差；严格同步仍以本地引擎为准。
- BPM 建议是规则估计，不是临床心率建议，也不构成运动或医疗指导。
