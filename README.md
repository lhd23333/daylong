# 朝夕 · 陪你过完这一天

一个跑在本机的陪伴型应用。把一天的日程放进去，它会替你算出**该在什么时候休息**、
写一句话**问候你今天的状态**，并在休息的那一刻**当场生成一段适合你的音乐**。

面向的场景很具体：高中生的一天被课表和自习切得很碎，真正能走开的空档不多，
而人一旦坐下来就很难自己想起来要起身。所以这个项目做的不是"再推荐一首歌"，
而是**把休息本身安排出来，并且让那段休息真的待得住**。

服务端只用 Python 标准库，浏览器端依赖固定版本的 Tone.js 并随包提供，**全程离线可用**。

## 它长什么样

三个页面：

- **今天** —— 顶部是一张关怀卡（问候 / 依据 / 建议），下面是整天的时间轴。日程和
  休息点串在同一条线上，中间插一根「现在」标尺。还没到的休息点是一张立起来的小卡片，
  过去的休息点收起卡片形态、退回成普通条目——卡片意味着"还用得上"。
- **了解你** —— 状态三个滑杆（精力 / 压力 / 专注）+ 睡眠与久坐时长、作息时间、
  今天的日程（手动添加或导入 `.ics`）、以及喜欢的音景。
- **休息** —— 选一个音景开始播放。有实时频谱、快慢 / 疏密 / 音量三个滑杆、
  「换一段」换调性和和弦进行，以及一条可选的"让 AI 直接生成一段音频"通道。
  还没开始放的时候，频谱区收成一条细线、快慢 / 疏密两个滑杆是灰的——省下的
  地方留给音景本身，也免得一条 92px 的空白看起来像没加载出来。

## 一天是怎么被排出来的

1. 前端把当前时间、当天的起止窗口、状态和作息发到 `POST /api/day`。
   不传 `events` 时后端用它自己保存的日程，避免两份数据打架。
2. `music_companion/day_plan.py` 把一天的窗口切成若干段：不可打断的日程是
   `protected`，其余是 `free_windows`。
3. 在两类位置安排休息点：
   - **可打断的长块内部**：一段超过 90 分钟的学习/工作，在第 90 分钟安排一次
     「出去走一圈」；
   - **空闲窗口**：按"已经连续学了多久"和"这个空档装得下什么"从
     walk / stretch / breathe / eyes / water 五类里挑。
4. 挑选时**优先选当天还没出现过的那一类**，而不是顺着固定的级联一路 `elif` 到底。
   这一条是为了避免一天下来四个休息点全写着「出去走一圈」——那读起来像机器排的。
5. `music_companion/soundscape.py` 按 **时段 +3 / 心情 +2 / 场景 +2 / 精力 +1**
   的打分制挑音景，同分时按 id 字典序取第一个，所以**同样的输入在任何机器上都得到
   同一个结果**。
6. `music_companion/companion.py` 把日程与状态整理成一组"事实"（睡了多久、距下一件
   还有几分钟、最长空档多长……），再从中选一条模板生成关怀语。模板里引用了空事实的
   措辞会被 `_usable()` 过滤掉，不会渲染出「还有  分钟」这种病句。
7. 返回一份 `timeline`：日程和休息点混排，每个休息点带 `soundscape` / `bpm` /
   `intensity` / `reason`。

## 音乐为什么不是循环播放

这是项目里唯一"重"的部分，也是最花心思的地方。

**没有音频文件。** 休息点的音乐是浏览器用 Web Audio 现场合成的，曲谱由算法即时决定：

- `static/js/theory.js` —— 音乐理论的翻译层。和声进行写成 `["2min9", "5dom9",
  "1maj9", "6min9"]` 这样的**级数记号**，好处是同一套进行可以搬到任意调上。
- `static/js/soundscapes.js` —— **程序库**。8 个音景，每个定义了性格、适用时段、
  心情、场景、BPM 区间、可选调性、7 条左右的级数进行、每小节几拍换和弦，以及
  4 个声部（键盘 / 铺底 / 铃音 / 贝斯）各自的音色、八度、增益和演奏方式。
  算下来 8 个音景 × 46 条进行 × 各自的调性与速度区间 = **4315 种组合**，
  界面右上角会把这个数字显示出来。
- `static/js/engine.js` —— 引擎。用 Tone.js 搭一条
  `bus → 滤波 → 合唱 → 混响 → 限幅 → 主输出 → 电平表/频谱 → 扬声器` 的链，
  外加一条 `滤波 → 反馈延时 → 混响` 的并行送出。每小节现算要弹哪些音，
  用固定种子的伪随机数决定琶音与留白，所以**同一段音乐可以复现，但不会原地循环**。

每个休息点用自己的 id 当随机种子，所以**同一个音景在不同休息点会落到不同的调性上**，
不会一整天听着同一段。

传输层是自己写的小节调度器，不是 `Tone.Loop`——原因写在 `engine.js:168` 的注释里：
`Tone.Loop` 按"回调收到的音频时间 + 构造时算出的固定秒数"自我重排，而事件本身是按
transport 秒数解释的，两个时间基准会漂移，几次切换音景之后事件就排到过去、被调度器
丢弃（实测第 3 小节后彻底静音且不报错）。换成显式调度后，所有时间只有一个基准，
新速度从下一小节起生效。

## 启动

不需要 Flask、Node 包或任何第三方 Python 库，只要有 Python 3.10+。

Windows 可以直接双击项目提交目录里的 `一键启动朝夕.bat`，脚本会自动定位项目、
检查 Python、启动服务并打开浏览器。

```bash
cd 项目源代码
python server.py
```

然后打开 <http://127.0.0.1:8000>。停止按 `Ctrl+C`，换端口用 `--port 8080`。

运行测试：

```bash
python -m unittest discover -s tests
```

> `tests/` 目录没有 `__init__.py`，所以**不要**加 `-t .`，否则会报
> `Start directory is not importable`。

## 连接 AI（可选）

不配任何密钥也能完整演示：关怀语走本地模板，音乐走浏览器实时生成。配上之后是两个
互不相干的增强通道——**文本通道改措辞，音频通道换声音**，各配各的，坏一个不影响另一个。

关怀语的 AI 通道走 `AIRecommender.care()`：`POST /api/day` 会先把本地关怀卡算好
（它永远是完整的），再把它连同今天的客观事实交给模型重写三句话。模型返回的内容要过
`_care_from_ai` 的检查——空字段、超长、出现「加油」「你可以的」这类空话，一律丢弃，
仍然显示本地版本。所以**打开这个通道最坏的结果是措辞没变，不会是没有关怀语**。

```bash
cp .env.example .env
```

```bash
# 文本通道：关怀语的措辞（OpenAI 兼容接口）
OPENAI_API_KEY=你的密钥
OPENAI_BASE_URL=https://api.minimax.cn/v1
OPENAI_MODEL=MiniMax-M3
MUSIC_COMPANION_AI=auto

# 音频通道：直接用模型生成音频，而不是浏览器合成（仅服务端读取）
ELEVENLABS_API_KEY=你的密钥
ELEVENLABS_BASE_URL=https://api.elevenlabs.io/v1
ELEVENLABS_MODEL_ID=music_v2_5
ELEVENLABS_TIMEOUT=120
```

配好后重启服务，访问 `http://127.0.0.1:8000/api/health`：

```json
{"ok": true, "mode": "ai", "audio_generation": true}
```

`mode` 为 `local` 说明没读到文本通道的密钥，功能仍然正常，只是关怀语换成模板。

诊断命令：

```bash
python tools/test_api.py
```

**密钥只放在本机 `.env` 里，不要写进前端、截图或提交材料。** `.env` 已在
`.gitignore` 中，`.env.example` 里只有字段名。

## 主要接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/soundscapes` | 音景目录（返回的是**裸数组**，不是包了一层的对象） |
| GET | `/api/calendar/events` | 日程列表，支持 `?date=YYYY-MM-DD` |
| GET | `/api/state/latest` | 最近一次状态快照 |
| GET | `/api/health` | 模式与能力探测 |
| POST | `/api/day` | **主接口**：编排一整天，返回 timeline / stats / care |
| POST | `/api/day/break-status` | 标记某个休息点为 started / done / planned |
| POST | `/api/calendar/events` | 新增日程 |
| POST | `/api/calendar/import-ics` | 导入 `.ics` |
| DELETE | `/api/calendar/events/<id>` | 删除日程 |
| POST | `/api/state/manual` | 保存状态快照 |
| POST | `/api/generate-ai-audio` | 调音乐模型生成音频，失败自动回落本地 WAV |
| POST | `/api/recommend` | 第一版的 BPM / 步频推荐（界面已不使用） |

日期时间字段一律要求**带时区**的 ISO8601（`2026-10-05T09:40:00+08:00` 或结尾 `Z`）。
不带时区会返回 400——这是刻意的，避免跨时区把休息点排错。

## 为什么这样设计

- **服务端只用标准库**。课堂电脑装依赖经常失败，而 `http.server` 零安装即可启动。
  需要"库"的地方（实时音乐）放在浏览器端，用固定版本随包提供，不依赖 CDN。
- **本地规则不是装饰，是基准**。关怀语和选曲在没有网络时是完整的，AI 只是把措辞
  和音频做得更好；任何一路失败都不影响主流程。
- **确定性优先**。选音景同分按 id 字典序、休息点 id 用 uuid5、音乐用固定种子——
  同样的输入在任何进程、任何机器上都得到同样的结果，便于复现和讲解。
- **能测的逻辑不放在前端**。编排、选曲、关怀语全在 Python 里，可以单独跑测试；
  前端只负责呈现和调度。
- **不假装**。AI 音频失败时响应头会写明 `X-Music-Source`，界面照实说"改用本地循环"，
  不把回退包装成成功。

## 已知限制

- 本地关怀语是模板 + 事实填充，不是真正理解长文本；AI 通道才会读用户写的备注。
- 休息点是按日程形状和状态推出来的，不理解"这节课特别重要不能打断"这类语义，
  需要用户把日程标成不可打断。
- 频谱可视化只画到约 1 kHz 以上的一段（实测再往上已经低于噪声底），是呈现上的
  取舍，不是完整频谱。
- 服务器仅供本地开发与演示，没有鉴权、限流和 TLS。
- AI 音乐的时长、旋律与 BPM 与提示词存在偏差；严格同步仍以本地引擎为准。
- BPM 建议是规则估计，不是临床心率建议，也不构成运动或医疗指导。
