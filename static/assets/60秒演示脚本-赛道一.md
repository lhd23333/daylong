# 60 秒演示脚本（赛道一）

> 每一步写清三件事：**点哪里 → 屏幕上会看到什么 → 这一步想让评委看到什么**。
> 计时按旁白正常语速估算，全程不离开应用。

## 准备（开始录制之前）

1. 双击 `一键启动朝夕.bat`，浏览器打开页面——**停在「对话」页**，确认有声音。
2. 在「了解你」页的「今天的日程」表单里加一条日程（标题 + 起止时间 + 类别），
   把它的开始时间设为**录制开始后约 5 分 50 秒**（例：20:00:00 开录，
   就把这条日程设为 20:05:50 开始）。这样录到第 50 秒前后，右下角会自然弹出提醒卡。
   如果录制节奏没对上，刷新一次页面也可以——窗口期内该响的提醒会补触发。
3. 提醒卡**不会自己消失**，一直停在那里，直到你点它的关闭按钮或「先听一段」。
   所以第 48 秒那一段不用赶，等它出来再讲。
4. 说话时点「试试这样说」的第一个示例芯片：「上午数学课，下午四点半去操场跑半小时」——
   一句话里带时段、钟点和跑步，排出来的日程与配乐最有得看。

## 0-06 秒：问题

- 操作：停在「对话」页，不点任何东西。
- 画面：「先说一句，今天怎么过」加一条输入框，下面是三条示例说法。
- 想给评委看的是：它不是"又一个播放器"，先解决的是"这一天怎么被安排"。
- 旁白："学生不是不想休息，是坐下来就想不起来。朝夕把日程、休息和音乐排进同一条时间轴。"

## 06-18 秒：一句话，日程和音乐一起排好

- 操作：点「试试这样说」的第一个示例，等它把结果摊开；然后点**「写进今天」**。
- 画面：同一页上出现它排好的时间轴、配上的音乐与记住的喜好；点「写进今天」后自动跳到
  「今天」页，时间轴上是刚排好的日程，每条日程下面跟着一行配乐（如「♪ 书桌前 · 69 BPM」），
  右侧有「放这首」。旁边那个按钮是「听这段」——不写日程，直接去「休息」页试听。
- 想给评委看的是：入口是一句话，不是一张表；说出来的话落到的是同一份日历与同一套音乐参数。
- 旁白："说一句今天怎么过，它排好日程、配好音乐。写进今天，就是今天的时间轴。"

## 18-23 秒：想自己动手也留了口子

- 操作：切到「了解你」页，指一下状态三个滑杆和「今天的日程」表单，不做修改。
- 画面：精力 / 压力 / 专注三个滑杆、睡眠与久坐时长、作息与日程录入都在。
- 想给评委看的是：一句话是入口，不是唯一入口；手动那一层没有因为多了对话而被砍掉。
- 旁白："不想说也行——状态、作息、日程，这里都能自己填。"

## 23-32 秒：音乐是现场合成的

- 操作：回「今天」页，点某条日程右侧的「放这首」。**页面会自动切到「休息」页**——
  播放器在那一页，这是设计好的动作，不是跳转错误。
- 画面：切页之后音乐立刻响起。播放器里一张光碟开始转（转速跟着 BPM，每小节转八分之一圈），
  光碟中心显示 BPM 与调性；频谱绕成光碟外的一圈——96 根径向柱子，低频在正上方、
  顺时针铺开、频率越来越高；背景是粒子。
- 想给评委看的是：音乐不是音频文件，是浏览器现场合成的，而且是**这条日程**的曲子。
- 旁白："这段音乐是浏览器现场合成的，不是循环播放的文件；每条日程都有它自己的那一首。"

## 32-43 秒：四条轴，推荐不是手铐

- 操作：「自己调这一段」面板默认展开。拖动「节奏量」滑杆，故意拖出轨道上暖色画出的
  推荐区间；再把「鼓点」从推荐档换到「强」；最后分别拖一下「音乐」与「鼓点」两条音量滑杆。
- 画面：拖出区间后**照样在放**，界面只在下方多出一行说明——「这一段原本不是为这个速度
  写的」；不弹窗、不阻止。鼓点那一行四档（无 / 轻 / 标准 / 强），当前音景推荐的那一档
  带一个小点；换档后拍子明显变了。两条音量滑杆各管一路，鼓点推到 70% 就是 0 dB。
- 想给评委看的是：音景 / 节拍 / 节奏量 / 鼓点四条轴完全解耦；推荐是方向，不是手铐；
  "音乐盖过鼓点"这种抱怨，用户自己就能拧回来。
- 旁白："音景、节拍、节奏量、鼓点是四条独立的轴。推荐区间只做说明，不拦着用户——拖出去，
  照样能听；拍子不够响，两条音量滑杆分开拧。"

## 43-48 秒：收藏存的是配方，不是音频

- 操作：点播放器上的「收藏」，**再点一次**；然后滚到下方「我的收藏」列表里点一条。
  （上一步的「放这首」已经把人带到「休息」页了，这里不用再切页。）
- 画面：按钮先变成实心的「已收藏」，弹出「已存进收藏」；第二次点击**不会取消收藏**，
  而是弹「这一段已经在收藏里了」——重复收藏是个确定答案，不是错误；
  「我的收藏」列表里那条能直接播放。
- 注意：提示条 2.6 秒后自己消失，别等它。
- 想给评委看的是：整条合成链路是确定性的，同一组八个字段永远得到同一段音乐，
  所以收藏只要存配方；"这段是不是已经收藏过"因此有确定答案。
- 旁白："收藏存的是配方，不是音频。同一组配方永远回到同一段音乐——这就是收藏的意义。"

## 48-54 秒：提前 5 分钟的提醒

- 操作：回到「今天」页，等右下角的提醒卡弹出（准备步骤里安排的那条日程）。
- 画面：提醒卡显示「还有 N 分钟」、日程标题、一句 why，以及「先听一段」。
- 想给评委看的是：提醒不是一句"该休息了"，它带着理由。
- 旁白："日程开始前 5 分钟提醒，并且告诉你为什么是这一段。"

## 54-60 秒：边界

- 操作：不做操作，画面停在提醒卡或时间轴上。
- 想给评委看的是：设计者清楚自己的能力边界，不吹。
- 旁白："提醒只在页面开着时有效，浏览器关掉没有后台能力；音乐离线可用、不依赖任何密钥。
  它是一个本地网页原型，不是常驻 App，也不做医疗判断。"
